# 分子动力学力场：怎么选、怎么配，缺参数怎么办？

> 节选自：https://mp.weixin.qq.com/s/yhcYMYLLtF0bV91xpaxVzQ

准备做分子动力学模拟时，很多人最先关心的是：体系有多大、需要跑多少纳秒、用什么软件、多久能算完。但在这些问题之前，还有一个更基础的问题：模拟中的原子，究竟根据什么规则运动？这个问题不清楚，后面就很容易出现一些误解：把计算软件当成力场，把水模型和蛋白参数混在一起，或者认为只要成功生成了拓扑文件，参数就已经可靠。

理解力场，需要先从分子动力学本身说起。

## 分子动力学的本质：知道原子在哪里，还要知道它下一步怎么动


在常见的经典分子动力学模拟中，我们首先建立一个体系，给定原子的初始位置和速度，再不断计算各原子受到的力，通过数值积分更新它们的位置与速度，最终得到随时间变化的轨迹。

其中，保守力与势能之间的关系可以写为：

再结合牛顿运动方程：

计算原子在下一个时间步如何运动。这一过程不断重复，才形成了我们看到的蛋白摆动、配体旋转、分子扩散或聚集过程。

问题也就自然出现了：这里的**势能U，从哪里来？**

在常规经典MD中，它通常由力场提供。力场用一套数学表达式和参数，根据当前结构计算体系势能，再由势能的变化得到作用力。因此，力场不是模拟开始前随手勾选的一个“小设置”，而是构建物理模型的核心部分。

还要区分一点：MD是一类模拟方法，并不等于某一种力场。接下来主要讨论常见的经典全原子力场；极化力场、反应力场等采用不同的物理描述，不能把它们的能力和适用条件混为一谈。

## 力场到底规定了什么？

以常见的生物分子固定电荷力场为例，势能通常可以概括为：

![](https://mmbiz.qpic.cn/sz_mmbiz_png/I9w7rdxpN59CMdicJFtLFHoDh2B1ow8LzPAhbzr175PHNjEK4s4cD9ribzzMGqz9typg4CCaK7S9XXaqSaUIGUl4Hpck5IzqdXIDjtXibaMUOc/640?wx_fmt=png&from=appmsg)

具体力场还可能包含额外的耦合项或修正项，但理解下面几类相互作用，就已经抓住了主要框架。

| 相互作用 | 主要描述什么 | 与研究结果有什么关系 |
|------|--------|------------|
| 键伸缩 | 化学键偏离平衡键长时的能量变化 | 影响局部结构与振动 |
| 键角弯曲 | 三个原子形成的夹角怎样变化 | 影响分子几何与局部柔性 |
| 二面角旋转 | 绕某根键旋转时的构象偏好与能垒 | 影响蛋白主链、侧链和配体构象 |
| 非正常二面角等几何项 | 描述平面性等局部几何特征 | 避免不合理的局部结构变形 |
| 静电作用 | 电荷之间的相互作用 | 影响分子识别、溶剂化、离子配位等 |
| 范德华作用 | 短程排斥和色散吸引 | 影响堆积、接触距离与相间分配 |

这些作用并不是彼此独立地决定结果。例如，一个配体绕某根键旋转时，不仅二面角能量发生变化，分子内部的静电、范德华作用，以及与溶剂的接触也可能同时改变。**不能把“构象是否合理”完全归结为某一个参数。**

此外，力场不只是参数表，还包括参数如何被分配和组合的规则。例如，不同原子之间的Lennard-Jones参数怎样组合，沿成键路径相隔三个键的“1–4原子对”如何处理，都可能因力场体系而不同。**两份参数都能被软件读取，不代表它们可以直接混用。**

## 常见力场有哪些？先看研究的是什么体系


理解了力场怎样描述相互作用，再看AMBER、CHARMM、OPLS等名称，就需要关注它们的描述对象和验证范围。面对不同的分子与研究目标，力场选型不能只比较名称。

常见名称并不都处在同一个层级：有的是力场家族，有的是针对某类分子的具体参数集，还有些是运行模拟或生成参数的工具。

| 名称 | 属于哪一类 | 应当怎样理解 |
|----|-------|--------|
| AMBER、CHARMM、OPLS | 力场家族 | 同一家族中可以包含不同分子类别、不同版本的参数 |
| ff14SB、ff19SB、CHARMM36m、OPLS-AA/M | 蛋白等生物分子的具体参数集 | 不能仅凭名称就认为任意药物、金属或修饰都有参数 |
| GAFF/GAFF2、CGenFF、OpenFF Sage | 小分子力场 | 用于其覆盖范围内的有机小分子 |
| GLYCAM、Lipid21等 | 特定分子类别的参数体系 | 分别面向糖类、脂质等组分 |
| TIP3P、TIP4P-Ew、OPC、SPC/E | 水模型 | 定义水的几何、相互作用位点、电荷和非键参数 |
| GROMACS等 | MD计算程序 | 根据给定模型计算作用力并推进模拟 |
| Antechamber、LigParGen、CGenFF程序等 | 参数分配或生成工具 | 帮助建立参数，并不等于重新开发了一套力场 |

AMBER这个名称还存在双重含义：它既可以指力场家族，也可以指软件套件，需要结合语境判断。分清这些层级后，再按体系查找相应参数。

**下面列的是有依据的选型入口，不是拿来机械套用的标准答案。**

### 生物分子体系：先辨认组分，再查对应参数

| 研究体系 | 可以从哪些参数体系开始查找 | 真正需要核对的内容 |
|------|---------------|-----------|
| 常规蛋白质 | AMBER ff14SB/ff19SB、CHARMM36m、OPLS-AA/M | 蛋白类别、构象状态、溶剂搭配，以及相关实验验证 |
| 蛋白—有机小分子 | 蛋白参数配合GAFF2、CGenFF、OpenFF Sage或相应OPLS小分子参数 | 配体化学环境、电荷方案、关键二面角，以及跨组分相互作用 |
| DNA、RNA及蛋白—核酸 | 专门的核酸参数，如AMBER的DNA、RNA参数体系 | DNA与RNA不能混为一谈；还要检查序列结构、修饰和离子条件 |
| 脂质膜、膜蛋白 | 专门脂质参数，如AMBER Lipid21等 | 脂质种类、膜组成，以及与蛋白、水、离子的兼容性 |
| 糖、多糖、糖蛋白 | GLYCAM等糖类参数体系 | 单糖立体化学、异头构型、连接位置、糖苷键及糖—蛋白连接 |
| 无序蛋白、柔性肽 | 查阅对相关无序状态有验证的参数组合，如CHARMM36m的相关研究 | 不能只看是否“稳定”，还要关注构象分布、整体尺寸和二级结构倾向 |
| 金属蛋白、金属酶 | 专门非键模型、成键模型，或针对问题采用QM/MM等路线 | 氧化态、配位几何、配位交换，以及是否涉及反应 |
| 非天然残基、翻译后修饰、共价配体 | 已验证的专用残基参数，或补充参数化 | 不只是新增基团，还包括它与原结构之间的新连接 |

蛋白、小分子与专用组分的选型依据，可分别查阅ff19SB、CHARMM36m、OPLS-AA/M的原始研究，以及AMBER官方的组分参数说明。

### 聚合物、溶液和材料：不能照搬蛋白体系的选法

| 研究体系 | 常见查找方向 | 关键适用条件 |
|------|--------|--------|
| 有机聚合物、凝聚态有机材料 | OPLS、COMPASS及针对特定聚合物开发的参数 | 单体与连接方式、立构规整性、链构象、密度及目标热力学性质 |
| 有机溶液、电解液 | 与溶剂和离子环境共同验证的参数组合 | 浓度、溶剂组成、离子配位、扩散及相间相互作用 |
| 矿物、黏土及水化界面 | ClayFF或适用的专门矿物参数 | 晶相、表面羟基化、表面电荷和水化结构 |
| 无机—有机、生物—材料界面 | INTERFACE及相关专用参数 | 具体材料是否被覆盖，以及有机—无机交叉作用怎样定义 |
| 较大尺度的膜、自组装、聚集过程 | Martini等粗粒化力场 | 粗粒化映射是否保留了研究所需的信息，不能直接替代所有原子级分析 |

COMPASS、ClayFF与INTERFACE分别有明确的开发背景和验证对象；Martini则属于粗粒化模型，研究分辨率与全原子力场不同。**力场名称出现在同一张表里，并不意味着它们描述的是同一层次的问题。**

对于电解液，还要特别谨慎：在水中拟合和验证的离子参数，不能未经检查就直接外推到任意有机溶剂或高浓度混合体系。应当核对其参数化环境，并结合目标体系的结构与物性数据评估。AMBER的离子参数说明本身就区分了不同水模型及不同拟合目标。一文搞清分子动力学力场_最终发布版

## 选好了蛋白力场，为什么还不能直接开始模拟？

## 

以一个在水溶液中进行的蛋白—小分子模拟为例，我们研究的对象虽然是蛋白和配体，但实际建立的体系还包含周围的水和离子。

因此，选择力场时，需要考虑的不只是蛋白采用什么参数，还包括配体、溶剂和离子分别怎样描述，以及它们之间的相互作用是否有合理的搭配依据。

**蛋白使用ff19SB，不等于配体也拥有ff19SB参数；蛋白使用CHARMM36m，也不等于任意小分子、辅因子和修饰都会自动被正确描述。**

GAFF的开发目标是与AMBER生物分子力场兼容的小分子描述；CGenFF则面向与CHARMM加和型生物分子力场配套的药物样分子。它们解决的是蛋白参数本身没有覆盖的化学空间，但依然需要检查具体分子的参数质量。

### 水模型，是完整参数组合的一部分

同样，**水也需要自己的相互作用模型。常见的TIP3P、TIP4P-Ew、OPC和SPC/E，属于水模型，规定水分子的几何、相互作用位点、电荷和非键参数。**

从广义上说，水模型也可以理解为专门描述水的一套力场；只是它的描述对象与蛋白参数、小分子参数不同，也不是包含多种生物分子参数的整个力场家族。

因此，阅读一篇模拟论文的方法部分时，看到蛋白力场、小分子力场和水模型同时出现，并不是作者重复列了几种“任选其一”的方法，而是在交代整个模拟体系中不同组分的参数来源。

水模型的具体版本，也属于需要核对的内容。原始TIP3P与CHARMM使用的修改版TIP3P存在差异。典型区别是：原始模型的氢原子没有Lennard-Jones相互作用，而CHARMM修改版为氢原子也设置了相应参数。复现文献时，不能只看到“TIP3P”几个字就认为所有实现完全相同。**水模型的具体版本和来源，同样需要核对。**

### 各组分都有参数，还要看它们能否配合使用

对于一个复杂体系，往往需要同时考虑蛋白、配体、核酸、糖链、膜、水和离子，而不是只为蛋白选一个名字。AMBER官方也明确提醒：组件之间的搭配需要关注联合使用的依据，随意组合不同来源的参数应更加谨慎。

这里既涉及函数形式、混合规则和1–4相互作用等实现细节，也涉及蛋白—水、配体—水、蛋白—配体等跨组分相互作用的验证依据。**每一部分都有参数，还不等于整个组合已经合理。**

### 两个有依据的搭配示例，应该怎样理解？

AMBER路线：蛋白从ff19SB出发，小分子采用适合其化学结构的GAFF2参数，水模型可考虑OPC，并使用有明确搭配依据的离子参数。ff19SB原始研究支持其与OPC这类水模型共同使用，但配体和特殊组分仍需单独检查。

CHARMM路线：蛋白采用CHARMM36m，小分子从CGenFF出发，再核对该参数体系使用的水模型、离子参数和非键处理设置。不能只把几个带有“CHARMM”字样的文件放在一起，就省略对具体版本和实现的检查。

这类组合可以作为研究设计的起点，**不是对任意蛋白、配体和实验条件的准确性保证。**

至此，力场选择才从“为蛋白选一个名字”，推进到“为完整体系确定一套有依据的参数组合”。接下来，还需要判断这套组合是否适合自己的研究问题。

## 怎么判断一个力场适不适合自己的体系？

判断适用性，建议依次回答六个问题。

### 第一问：这个模型能不能描述我关心的过程？

这一问应该放在最前面，而不是参数生成之后。研究非共价接触、构象变化和扩散，与研究断键、成键、质子转移或氧化还原，面对的是不同的模型需求。

例如，用固定成键拓扑的模型描述已经形成的共价复合物，与模拟共价键如何形成，不是同一件事。反应力场可以描述其设计范围内的反应过程，但仍然需要对应的参数集；不能因为软件支持ReaxFF，就认为所有反应都能可靠计算。先判断物理描述是否成立，再讨论具体参数。

### 第二问：覆盖的是我的化学环境，还是仅仅覆盖了这些元素？

一个分子只含C、H、N、O，并不意味着它一定容易参数化。相同元素可以处于不同的杂化、共轭、电荷和环张力环境中；参数分配需要识别的是这些化学环境，而不只是元素列表。GAFF与CGenFF的参数分配逻辑，都包含对局部化学类型的判断。

因此，应当追问：现有参数来自相似化学环境，还是只是程序勉强找到的近似项？

### 第三问：参数是直接匹配的、类比得到的，还是重新拟合的？

“参数生成成功”只能说明工具给出了结果，并不能说明各部分具有同等可信度。以CGenFF程序为例，它会为分配的参数和电荷提供penalty score，用于提示类比的不确定性。常见指导区间是：低于10时类比较好；10—50需要基本验证；高于50需要更深入的验证，并视情况优化。**这些不是能量单位，也不是准确率百分比，更不是普遍适用于所有工具的评分。需要重点检查的是：不确定性较大的参数，是否恰好位于决定研究结论的部位。**

### 第四问：整套参数能否协调工作？

兼容性至少有两个层面。一个是**实现层面**：函数形式、单位、混合规则、1–4处理及特殊修正是否一致。另一个是**物理层面**：蛋白—水、配体—水、蛋白—配体这些跨组分相互作用，是否有联合使用和验证依据。

不同力场之间并非绝对不能组合，但不能仅凭“都是全原子力场”就认为可以直接混用。OPLS的官方说明就明确强调，其Lennard-Jones组合规则与1–4处理需要被正确保留。

### 第五问：文献验证的条件，和我的条件有多接近？

查文献不能只搜索“这个蛋白有人用过什么力场”。更应该看：验证对象是折叠蛋白还是无序状态？研究的是稀溶液还是高浓度体系？是否包含膜、金属、修饰或特殊溶剂？验证的是结构，还是目标热力学性质？

例如，CHARMM36m原始研究关注折叠蛋白与无序蛋白的构象描述。这能为相关选型提供依据，但不能据此推导出“它适用于所有无序蛋白和全部溶液条件”。

### 第六问：什么数据能够证明它适合回答我的问题？

**验证指标应该跟着科研问题走，而不是永远只看RMSD。**

| 研究重点 | 更有针对性的验证内容 |
|------|------------|
| 配体或肽的构象偏好 | QM相对构象能、关键二面角势能曲线，以及可获得的实验构象信息 |
| 无序蛋白是否过度紧缩 | SAXS、NMR等实验约束下的构象系综和整体尺寸 |
| 溶液与混合物的相互作用 | 密度、混合热、溶剂化或转移自由能等 |
| 离子配位 | 配位距离、配位结构，以及相应实验或QM参照 |
| 材料及界面 | 晶体结构、表面性质、水化或吸附相关数据 |

这些验证思路分别对应了蛋白、小分子、离子和界面力场开发中实际使用的数据类型。**验证不是找一张“看起来正常”的轨迹图，而是让模型接受与研究目标相关的检验。**

## 做力场，真正难在哪里？

### 难点之一：部分电荷不是一组脱离环境的“标准答案”

常见固定电荷力场给每个原子分配固定的部分电荷，但真实分子的电子分布会受到化学环境影响。

更重要的是，原子部分电荷并不是可以唯一直接测量的量。不同电荷方案采用不同的定义与近似，并与其他参数共同构成模型。**不能简单认为某种电荷来自更高水平的量子化学计算，就必然能让现有力场整体更准确。**

因此，使用AM1-BCC、RESP或其他电荷方案时，应首先遵循所选力场的参数化逻辑，而不是把不同来源的电荷随意替换进去。

当环境极化成为关键因素时，可以评估极化力场。例如AMOEBA显式描述极化响应，但它同样需要适用参数和验证，而不是固定电荷模型的无条件替代品。

### 难点之二：二面角不是把一条QM曲线“抄进去”

某根键旋转时，QM总能量的变化可能同时包含共轭、位阻、分子内静电及氢键等贡献。而在经典模型中，其中一部分已经由其他能量项描述。拟合二面角参数时，需要考虑**现有MM模型与QM参考之间的差异**，不能直接把QM势垒数值当作某个二面角系数。

ffTK等参数化工具正是通过比较QM扫描与MM描述，优化相应的二面角参数。这也意味着：修改电荷或其他相关参数之后，原先拟合良好的构象势能面可能需要重新检查。

### 难点之三：一个性质拟合得好，不等于所有性质都变好

力场通常需要同时兼顾结构、构象能、溶剂化、密度等多个目标。参数可能出现补偿：一项描述偏强，另一项偏弱，某个最终指标仍然看起来合理。

因此，力场开发不仅是“把误差降到最低”，还涉及训练数据选择、不同目标的权重、参数约束和独立验证。ForceBalance等工具将这些内容纳入系统化优化流程，但不会替研究者决定哪些物理问题最重要。

### 难点之四：参数必须在没有见过的体系里继续有用

通用力场不可能逐一拟合所有分子，只能将已有化学环境的参数迁移到新分子。

OpenFF Sage 2.0的开发就是一个具体例子：研究者利用凝聚态数据优化部分非键参数，再利用QM结构和扭转数据优化成键参数，之后通过训练集之外的数据进行验证。这说明，**开发通用力场需要同时考虑分子内部、分子之间，以及新化学环境中的表现**；只拟合一个分子的最低能构象，远远不是同一件事。

## “做力场”到底怎么做？先分清三个层次

日常交流中的“给这个分子做力场”，可能指三种不同工作。

**第一层：分配现有参数。调用已有力场，识别化学环境、分配原子电荷与相互作用参数，再生成模拟所需文件。**

**第二层：补充或修正部分参数。现有力场覆盖了大部分结构，但某些特殊官能团、关键二面角或金属中心需要额外处理。**

**第三层：开发一套新的通用力场。需要建立训练与验证数据集，优化大量参数，评估跨分子、跨性质的可迁移性。**

多数常规项目面对的是前两层。**下载一个拓扑文件，不等于开发了一套新力场。**

### 对普通有机小分子，一条合理的工作路线是什么？

#### 先把化学结构确认清楚，至少明确元素、连接关系、键级、立体化学、形式电荷、质子化状态和互变异构体。PDB主要提供坐标，并不总能无歧义地表达小分子的完整化学结构。参数工具需要可靠的化学图，而不是仅凭一团原子坐标猜测。

#### 

#### 再选定参数体系，完成初始分配，先决定使用GAFF2、CGenFF、OpenFF或其他适用路线，再按相应规则分配参数。

#### 

#### 随后检查缺失项、类比项、警告、电荷总和，以及关键部位的构象描述。不能因为程序没有中断，就跳过这一步。

#### 

#### 只有发现明确问题，才针对性补充QM计算

需要的工作可能包括几何优化、静电相关计算、振动信息或关键二面角扫描。

但**不必把所有分子都机械地执行一遍“优化—算电荷—扫所有键”**。应根据问题选择计算：是局部几何不对，还是电荷类比不可靠，抑或某根键的构象偏好决定了研究结论？ffTK的不同模块就是针对不同参数目标设计的。

#### 拟合之后，用没有参与拟合的数据检查

除了拟合曲线本身，还应检查其他相关构象、相对能量和目标性质。对溶液问题，只验证气相最低能结构通常不够；对构象问题，也不能仅检查一张优化后的结构。

训练数据与验证数据分开，才能判断参数是否只是在“记住”已有样本。

#### 最后检查参数如何进入完整体系

需要确认新参数的命名、连接关系、电荷和模拟程序实现。

特别是修饰残基、共价配体和糖—蛋白连接：问题不仅是新基团本身，还包括它与原分子之间新增的键、角和二面角。金属中心的成键参数化同样需要明确整个配位环境，而不是只对金属原子单独赋值。

## 哪些参数化网站和工具值得收藏？


先说明：以下工具不是同一类产品。有些主要分配现成参数，有些帮助建立完整体系，还有些需要在本地开展QM辅助拟合。

### 常规分子参数与体系构建

| 工具与官方入口 | 主要用途 | 使用时重点看什么 |
|---------|------|----------|
| Antechamber / AMBER | AMBER小分子参数化路线，常与GAFF/GAFF2及其他AmberTools组件配合 | 电荷方案、原子类型、补充参数的来源；参数分配不等于全部重新拟合 |
| CGenFF | 为适用的小分子分配CHARMM通用力场参数 | 检查参数和电荷的penalty，不要只下载结果文件 |
| LigParGen | 生成OPLS-AA兼容的小分子参数 | 它提供的是特定OPLS-AA参数化路线，不能等同于任意OPLS版本 |
| SwissParam | 在线生成小分子参数 | 记录使用的具体路线，不能笼统写成“SwissParam力场” |
| OpenFF Toolkit | 基于直接化学感知为小分子分配参数，可用于脚本化流程 | 化学结构必须明确；记录力场版本、电荷方法和输出工具 |
| ATB | 自动参数化与参数库检索，主要提供GROMOS兼容路线 | 输出格式不等于力场家族；还要先看公开性与使用条件 |
| CHARMM-GUI | 帮助构建蛋白、膜等完整模拟体系 | 它是建模与输入生成平台，不代表所有特殊化学环境都已可靠参数化 |

这些用途分别对应各工具的官方说明及方法论文。

其中有几个细节值得单独记住。

LigParGen输出的是OPLS-AA兼容参数。即使下载的是GROMACS或CHARMM程序可读的文件，也不意味着参数变成了GROMACS“力场”或CHARMM36参数。**文件格式兼容和力场兼容，是两回事。**

SwissParam需要区分参数化路线。2023年更新后，它除了改进的MMFF衍生路线，也提供通过MATCH使用CGenFF的路线；这与直接使用官方CGenFF程序并不是完全相同的工作流。

OpenFF需要记录具体版本。它持续更新参数与电荷方案，不能把不同版本的设置笼统归为“用了Sage”。正式计算前应查看对应版本的发布说明，而不是默认沿用旧教程中的全部设置。

### 需要补参数、做QM拟合时

| 工具与官方入口 | 更适合什么任务 | 不应误解为什么 |
|---------|---------|---------|
| ffTK | 辅助开展小分子的电荷、键角和二面角参数优化 | 不是无需化学判断的一键生成器 |
| OpenFF BespokeFit | 面向具体分子开展定制化参数优化，尤其是扭转参数 | 不是对任意特殊分子所有相互作用的自动保证 |
| MCPB.py官方教程 | AMBER路线下金属中心成键模型的参数构建 | 不能替代对氧化态、配位、自旋及模型适用性的判断 |
| ForceBalance | 根据QM与实验参考数据系统优化力场参数 | 需要研究者定义目标、数据和优化策略，不是上传分子即可完成通用力场开发 |

ffTK、BespokeFit、MCPB.py和ForceBalance解决的是不同层次的问题，不能因为都与“参数化”有关，就互相替代。

## 最容易踩的坑，不一定是“找不到参数”

很多明显错误会让程序直接报错，反而容易发现。更危险的是：文件生成了、轨迹跑完了，但模型与研究问题并不匹配。

| 常见做法 | 真正的问题 |
|------|-------|
| 只有PDB坐标，就让工具自动推断所有化学信息 | 键级、芳香性、质子化和形式电荷可能不明确 |
| 总电荷正确，就认为化学状态正确 | 不同质子化位置或互变异构体可能具有相同总电荷，却是不同模型 |
| 只要都能导出.itp，就混在一起使用 | 文件格式不保证混合规则、1–4处理及物理兼容性 |
| 参数转换后能运行，就认为转换无误 | 仍需检查单位、特殊项和能量表达是否保留 |
| 只拟合一个最低能构象 | 可能遗漏其他重要构象及构象间能垒 |
| 对金属配位键建立固定成键模型，再用它证明“不会解离” | 模型本身已对这种行为施加限制，结论存在循环 |
| 给修饰基团单独生成参数，再直接接到蛋白上 | 连接边界的新参数与电荷分配可能没有处理完整 |
| 哪套参数给出预期结果，就选哪套 | 这是用期待代替独立验证，不能证明模型更可靠 |

化学信息、参数分配、实现规则和金属建模等风险，分别可以在OpenFF、CGenFF、OPLS与MCPB.py的文档和方法研究中找到对应依据。

跨程序转换时，一个实用检查是：用相同坐标，在尽可能一致的计算条件下比较转换前后的单点能量分项，必要时检查作用力。比起“两个程序都能跑”，这更接近检查同一个模型是否被正确实现。该检查建议直接来自力场由势能函数、参数和计算规则共同定义这一事实。

另外，还要区分两类问题：

- 采样问题：在当前模型下，访问到的构象和统计是否足够。
- 模型问题：当前势能表达、化学状态和参数，是否适合真实体系。

延长模拟主要改善前者，不能自动修复后者。一个体系运行得很稳定，最多只能说明它在当前模型和设置下表现稳定，不能仅凭这一点证明模型准确。

## 最后，把力场选择落实成一张可执行的清单 

开始正式模拟之前，应当能够清楚回答：

- 研究问题是什么？关心构象、识别、扩散、聚集、配位，还是化学反应？
- 模型能否描述这个过程？常规固定拓扑力场是否足够？是否需要其他物理描述？
- 体系包含哪些组分？蛋白、配体、核酸、糖、膜、金属、修饰、溶剂和离子，分别采用什么参数？
- 参数依据是什么？具体版本、来源、电荷方案、特殊参数和联合使用依据是否明确？
- 哪些地方最不确定？缺失参数、高penalty、特殊二面角、配位中心或新连接是否处理过？
- 用什么数据验证？验证指标是否真的对应本项目的科学问题，而不是只看轨迹是否“好看”？
- 方法记录也不应只写“使用某某力场”，而应至少保留：各组分参数来源与版本、水模型和离子参数、配体电荷方案、特殊参数的处理方式，以及影响结果的非键计算设置。

这些记录既服务于复现，也方便日后判断：结果出现差异，到底来自化学模型、参数、实现，还是采样。

**理解力场，最终不是记住更多名称，而是学会判断：这套参数为什么能用于我的体系，又在哪些地方需要证据。**

跑多少纳秒很重要。但在此之前，更重要的是把模型选对、把参数用对，并知道该用什么方式检验它。
